CONTEXTFLOW · ATTENTION 示例讲解 · 实验 1 的第一步

同一个观测，看看动作计算如何分配注意力

固定案例：原始布局 · 正确牛奶示范 · episode 0 · 环境第 0 步。复用实验 0 的记录，所有切换都不运行模型，也不让机器人移动。

先分清三个“位置”

① 环境步：机器人走到哪了

本例始终是第 0 步。当前画面和机器人状态不会随下方控件改变。

② 采样步：动作生成到哪了

固定观测下，模型从噪声开始，用 10 次更新生成一段动作。这里保存了第 0、5、9 步的内部计算。

③ 层：这次计算到了哪层

每个采样步内部又经过多层 Transformer。这里保存第 0、9、17 层。所有编号从 0 开始。

示例默认看最后一次采样更新的最后一层。attention 是该更新内部的权重；不是对最终动作的贡献分解。

1. 固定一组计算坐标

一个 action query 对应预测动作序列中的一个时间位置，不是某个 x/y 动作分量。默认对前 5 个位置取平均，它们对应本轮会执行的动作范围；不包含当前 state query。所有视图均对 8 个 heads 取平均。

不同 head 或动作位置可能有不同分布，平均后看不到全部差异。此页面用于理解口径，不用于穷尽分析。

2. 原图 → 16×16 权重 → 热图

每个 patch 对应输入图像的 14×14 像素，顺序为从左到右、从上到下。鼠标移动到右侧图可读出单格的精确数值。没有做平滑插值或物体分割。

这真的是“模型在看这些像素”吗？

这是 action query 对带有图像位置索引的 token 的直接 attention。图像 token 已经过 SigLIP 和其他层的信息混合，不只包含本地 patch 的像素信息。因此有空间位置，但不是精确的像素因果归因。也没有在这里做跨层 attention rollout。

3. 先看总量，再读局部亮色

全部 keys 的注意力分配

按 token 权重求和；右侧同时标出有效 token 数。它们的数量不同，不能把求和结果直接当成公平的模态重要性评分。

keys 部分数量绝对比例条对全部 keys

语言中，哪些 token 分到了权重

保留 <bos> 和换行符；padding 已屏蔽。百分比仍以全部 keys 为分母，不是把语言单独归一化到 100%。

直接 attention 权重低 ≠ 语言不起作用。预测动作 token 权重大，也不等于“模型只依赖自己”。value 向量、残差和其他层的信息路径都尚未包含在这个数字中。

4. 用一个格子算明白

恢复默认值后，找到主视角权重最大的格子。下面同时给出两个分母，避免把“图像内百分比”误当成“全部输入百分比”。

颜色只把权重映射成深浅。如果对每张图单独调亮，同样的亮黄色可以代表完全不同的权重；所以必须同时读刻度和该相机的总量。

主图对应的数组操作
# 原始轴：采样步、层、batch、head、query、key

5. 推荐按这个顺序试一遍

  1. 保留默认值，读主视角、手腕图像、语言的总量。
  2. 只切换“颜色刻度”。注意图像会变亮，但百分比不变。
  3. 恢复共用刻度，固定采样步 9，把层从 0 切到 9、17：同一轮内部不同深度的计算。
  4. 固定层 17，把采样步从 0 切到 5、9：动作生成过程的不同阶段，机器人仍未移动。
  5. 最后比较第一个动作位置、前 5 个和全部 50 个的平均，观察汇总口径是否掩盖差异。

本例能说明如何读图，不能证明模型识别了牛奶、按位置行动或受哪个模态控制。这些问题留给之后的跨条件分析和干预。
